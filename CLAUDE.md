# LetrasIQ — Claude Code operator guide

You are the interface to **LetrasIQ**, a local font-design toolkit. The human describes fonts and redesigns in conversation; you edit source files and run CLI tools. There is no web app, no API, no accounts.

Always work from the repo root with the project venv active (`source .venv/bin/activate`). Prefer the `letrasiq` CLI over ad-hoc Python unless debugging.

---

## Mental model

| Path | Role |
|------|------|
| `fonts/<name>/spec.json` | Global style (metrics, knobs, `classification`/`subtype`, mood, notes) |
| `letrasiq/data/classifications.yaml` | Font-type taxonomy → default knobs + construction notes (brand-free) |
| `fonts/<name>/glyphs/*.json` | Per-glyph source: `parametric` (skeleton) or `custom` (SVG `path`) |
| `fonts/<name>/locked.txt` | Glyphs that must not be regenerated by global/template updates |
| `fonts/<name>/references/` | Sketches / images the human provides |
| `fonts/<name>/CHANGELOG.md` | Short dated log of accepted changes |
| `fonts/<name>/build/` | Compiled OTF/TTF/WOFF2, UFO, previews (binaries gitignored; commit latest preview PNGs) |
| `letrasiq/` | Python package (engine + CLI) |

**Filenames on case-insensitive disks:** uppercase single letters are stored as `A_.json` (UFO-style). Glyph *names* inside the font remain `A` / `a`.

**MVP charset:** A–Z, a–z, zero–nine, space, period, comma, exclam, question, colon, semicolon, quotesingle, quotedbl, parenleft, parenright, hyphen.

## CLI cheat sheet

```bash
letrasiq new <name> --spec spec.json
letrasiq build <name>                    # full pipeline + specimen
letrasiq build <name> --glyphs g,R,a      # still builds full font; prefer after local edits
letrasiq preview <name>                  # specimen PNG → build/previews/specimen.png
letrasiq check <name>                    # validate; non-zero exit on errors
letrasiq compare <name> --ref <git-ref>   # before/after → build/previews/compare.png
letrasiq fork <name> <new-name>           # copy sources for a variant
letrasiq trace <name> <glyph> <image>     # potrace sketch → custom glyph (+ lock)
letrasiq import-ufo <name> <path.ufo>     # pull editor glyphs → custom + lock
```

After `build` / `preview` / `compare`, **open and look at the PNG** (`build/previews/specimen.png` or `compare.png`) before declaring success. Do not ask the human to judge a change you have not inspected.

## Classification taxonomy

Source of truth: `letrasiq/data/classifications.yaml` (never put commercial font names there).

1. Infer `classification` + `subtype` from the human’s brief (see hints below).
2. Put those fields in `spec.json`. On `letrasiq new`, taxonomy **defaults fill knobs not present in the JSON**; explicit knobs win.
3. Read `traits`, `construction`, and `engine_support` from the entry via:

```python
from letrasiq.classification import resolve
info = resolve("sans-serif", "neo-grotesque")
# info.defaults, info.construction, info.engine_support, info.inspired_by_traits
```

4. If `engine_support` is `stub` or `partial`, warn the human up front and lean on custom/trace/import-ufo.
5. Critique the specimen against the subtype’s construction notes, not just raw knobs.

### Famous-name → subtype hints (disambiguation only — never clone)

| If they say… | Prefer |
|--------------|--------|
| Helvetica / Arial / Univers-like | `sans-serif` / `neo-grotesque` |
| Futura / Avant Garde-like | `sans-serif` / `geometric` |
| Gill Sans / Frutiger-like | `sans-serif` / `humanistic` |
| Franklin Gothic-like | `sans-serif` / `gothic` |
| Akzidenz / older gothics | `sans-serif` / `grotesque` |
| Garamond / Bembo-like | `serif` / `old-style` |
| Baskerville / Times-like | `serif` / `transitional` |
| Bodoni / Didot-like | `serif` / `modern` |
| Rockwell / Egyptian-like | `serif` / `slab` |
| Courier-like | `monospace` / `slab-mono` |
| Menlo / Consolas-like | `monospace` / `sans-mono` |

Say you are **inspired by those traits**, set classification/subtype, and design from the YAML — do not recreate a proprietary font.

## Ambiguity & questions

Hard rails (CLI, files, locks, OFL/no-clone, inspect PNG + `check`, taxonomy merge) are deterministic. **Aesthetic judgment is not** — and that is intentional.

Before `letrasiq new`, if the brief is underspecified enough that subtype choice would be a guess, ask **1–3** clarifying questions — then proceed. Prefer:

1. **Use** — text / UI / display / logo / code?
2. **Structure** — sans / serif / mono / “you pick”?
3. **Weight/width vibe** — light–bold, condensed–wide, or “neutral is fine”?

Skip any question already answered by the brief (e.g. “heavy geometric display sans” → no interrogation). Never re-ask after they have accepted a direction.

## Workflow: new font

1. Turn the human’s description into a `spec.json`. **First** pick `classification` + `subtype` from the taxonomy; then override knobs only where the brief differs.
   - weight, contrast, width, slant ∈ `[0, 1]` (slant small; ~0.15 ≈ gentle italic shear)
   - `serif_style`: `none` | `slab` | `bracketed` | `hairline`
   - `terminal_style`: `flat` | `round` | `sheared` | `ball`
   - `corner_roundness`, `aperture` ∈ `[0, 1]`
   - `mood` / `notes`: free text for you (engine ignores `mood`)
2. `letrasiq new <name> --spec …` then `letrasiq build <name>`.
3. Open `fonts/<name>/build/previews/specimen.png`.
4. **Critique honestly** before showing the human: consistency across related glyphs, spacing in sample words (not just the alphabet), whether the face matches the description **and subtype construction notes**, broken punctuation/dots, collisions.
5. Fix issues (global → edit `spec.json` + regenerate unlocked templates; local → edit glyph JSON). Rebuild, re-check the PNG.
6. Iterate until it looks right, **then** show the specimen and your short critique.
7. On acceptance: append CHANGELOG, `git commit` (see Versioning).

To regenerate parametric unlocked glyphs after a global spec change:

```python
from letrasiq.pipeline import regenerate_unlocked_from_templates, build_font
regenerate_unlocked_from_templates("<name>")
build_font("<name>")
```

Custom and locked glyphs are left alone.

## Workflow: redesigns

Decide **global vs local** from the request:

| Signal | Action |
|--------|--------|
| “heavier / wider / more contrast / add serifs / rounder” | Edit `spec.json` → regenerate unlocked templates → `build` |
| “fix the R / make g’s bowl bigger / tweak period” | Edit that glyph’s JSON → `build` (optionally `--glyphs …`) |
| Mix | Do global first, then local fixes; never let a global regen clobber locked/custom glyphs |

**Always** after a meaningful redesign:

1. `letrasiq build <name>`
2. `letrasiq compare <name> --ref HEAD` (or the last accepted commit)
3. Open `compare.png` and describe before/after briefly
4. Show the human the compare (and specimen if useful)

**Locked glyphs:** If the change would overwrite a name in `locked.txt`, **ask first**. Do not silently replace hand-edited or traced glyphs. The CLI does not hard-block file edits — you must.

---

## Workflow: variants (bold / condensed / italic)

1. `letrasiq fork <name> <new-name>`
2. Edit the new font’s `spec.json` (`weight`, `width`, `slant`, `style_name`, `mood`)
3. `regenerate_unlocked_from_templates` + `build`
4. `check`, preview, critique, then show

Do **not** mutate the parent font in place for a named variant.

---

## Workflow: sketches

When the human drops an image into `fonts/<name>/references/` (or gives a path):

1. `letrasiq trace <name> <glyph> <image>` (requires system `potrace`)
2. Inspect the custom glyph + rebuild + preview that character in context
3. Refine: edit the custom SVG `path` in the glyph JSON, or re-trace with `--threshold`, or convert carefully to parametric if it should follow the family
4. Traced glyphs are **locked** by default — keep them locked unless the human wants them parametric again

---

## Workflow: external editors (FontForge, etc.)

1. Human edits the UFO under `build/` or a copy
2. `letrasiq import-ufo <name> path/to/Edited.ufo` (optionally `--glyphs A,g,R`)
3. Imported glyphs become `custom` and are appended to `locked.txt`
4. `build` + `check` + preview

Ask before importing over glyphs the human did not mention.

## Versioning, undo, history

**Commit only after the human accepts** (“looks good”, “commit this”, etc.).

1. Append one line to `fonts/<name>/CHANGELOG.md` explaining *why*
2. Stage font sources + preview PNGs (not `.otf`/`.ttf`/`.woff2`/`.ufo` binaries)
3. Commit message format:

```text
font(<name>): <why>
```

Examples: `font(letra-sans): raise x-height for friendlier text`, `font(letra-sans-bold): fork and set weight 0.72`.

**Undo / go back to version X**

- `git checkout <ref> -- fonts/<name>/` then `letrasiq build <name>`
- Or `git show <ref>:fonts/<name>/glyphs/g.json` to inspect one glyph
- Prefer restoring paths over destructive resets unless the human asks

**“Show me the history of the g”**

```bash
git log -p -- fonts/<name>/glyphs/g.json
# uppercase:
git log -p -- fonts/<name>/glyphs/G_.json
```

Summarize the story in plain language; quote diffs sparingly.

## Taste rules

1. **Consistency first** — related shapes (E/F/L, n/h/m, O/C/G) should share construction logic.
2. **Judge words, not only the alphabet** — read the pangram and sample words on the specimen (`hamburgefonstiv`, `Typography`, etc.).
3. **Spacing** — if pairs look wrong, fix sidebearings via shape class / glyph edits; re-`check`.
4. **Honesty** — say when the parametric engine’s faceted curves look crude; improve skeletons or mark glyphs custom rather than overselling.
5. **Never copy a named commercial font.** Map named references → `classification`/`subtype` via the hint table, quote `inspired_by_traits` from the YAML, and design from knobs + construction notes — do not recreate a proprietary design.
6. **OFL by default** — each font ships `OFL.txt`; do not strip license metadata from builds.
7. **Nondeterminism is allowed** — two runs of the same vague brief may produce different faces. Same rails and taxonomy; divergent taste is expected. Convergence happens through human accept/reject and `compare`, not by freezing creativity into scripts.

## Glyph JSON shapes

**Parametric**

```json
{
  "type": "parametric",
  "skeleton": [
    {"kind": "stroke", "points": [[x, y], [x2, y2]], "closed": false},
    {"kind": "curve", "points": [[x,y], [cx1,cy1], [cx2,cy2], [x2,y2]], "closed": false}
  ],
  "overrides": {"weight_scale": 1.0}
}
```

**Custom**

```json
{
  "type": "custom",
  "path": "M … Z",
  "width": 600
}
```

Coordinates are UPM font space (Y-up). After edits: `build` → look at PNG → `check`.

## Definition of done (every request)

- [ ] Right command(s) run successfully
- [ ] Specimen or compare PNG inspected by you
- [ ] `letrasiq check <name>` clean enough to ship (fix errors; mention warnings)
- [ ] Honest critique relative to the human’s brief
- [ ] On accept: CHANGELOG + commit with `font(<name>): …`
- [ ] Locked glyphs respected (or explicit human OK)
